# 本地上下文压缩

Updated: 2026-08-05

AutoFilm Core 参考 Codex 的活动历史替换方式管理主 Agent 上下文。这里的“本地”指
压缩决策、分块、历史替换和持久化由 Core 完成；摘要仍通过当前默认模型供应方生成，
不调用供应方专用的远程压缩接口，也不要求在群晖运行本地大模型。

## 数据边界

- `messages` 保留用户、Agent、工具调用和工具原始结果，不因压缩删除或覆盖。
- `conversation_compactions` 每个会话只保存最新替代视图，包括压缩截止序号、状态
  摘要、近期用户原话、估算 Token 和压缩次数。
- `conversation_topic_summaries` 仍只负责切换影视作品后的长期主题摘要。它与通用
  上下文压缩用途不同，不能互相替代。
- `/new`、`/clear` 和 `/reset` 删除当前会话消息、影视主题状态和通用压缩快照；
  成员长期记忆不受影响。

恢复会话时，模型输入从最新压缩快照开始，再追加截止序号之后的新消息。SQLite 中
更早的原始工具结果仍可用于管理和排查，但不会再次全部发送给模型。

## 模型配置

每个模型配置保存三个上下文参数：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| 上下文窗口 | 128,000 Token | 供应方为该模型提供的完整窗口 |
| 自动压缩阈值 | 窗口的 80% | 请求前达到该值时执行本地压缩，最高允许窗口的 90% |
| 单工具输出预算 | 12,000 Token | 只限制模型视图，原始工具结果仍写入 SQLite |

模型的真实窗口与默认值不一致时，应在“AI 与模型”页面填写供应方实际值。Core 使用
跨协议保守估算在发送前判断，供应方返回的 `input_tokens`、`prompt_tokens` 或同类
用量用于同一任务的下一次判断。

## 执行流程

1. Core 构造系统提示词、成员长期记忆、影视主题摘要和当前活动消息。
2. 工具结果按模型的单项预算生成受限视图；工具原始结果保持不变。
3. Core 同时估算消息和工具定义所需 Token，并读取上一模型响应的输入 Token。
4. 两者任一达到自动压缩阈值时，Core 读取尚未压缩的完整用户请求。
5. 压缩材料过大时按不超过上下文窗口 50%、最高 48,000 Token 分块；每一块都用
   `conversation.compactor` 更新上一块摘要，请求不提供任何工具。
6. Core 保留最多约 20,000 Token、且不超过窗口 15% 的近期用户原话，并把最终
   摘要和截止序号写入 `conversation_compactions`。
7. 当前任务重新构造模型输入，继续原来的工具选择、下载、升级或字幕操作。

压缩检查发生在每次主 Agent 模型调用之前，所以一次用户请求内部也可以多次压缩，
不需要等下一条聊天消息。并行工具调用仍按调用 ID 保存结果顺序；压缩只发生在一轮
工具结果全部写入之后，不会留下半个调用。

## 摘要要求

`conversation.compactor` 保存在 `prompt_configs`，管理员可从提示词页面修改。默认
提示词要求保留：

- 当前目标、用户确认、限制和有效偏好；
- 已完成、运行中、等待、失败和部分成功状态；
- Jellyfin、TMDB、任务、工作流、候选、字幕 workspace 和放置计划等稳定 ID；
- 下载或资源升级完成后还需要执行的字幕和通知事项；
- 外部修改是否已经取得同意。

搜索结果长列表、失效链接、协议说明和无后续意义的日志不进入摘要。工具仅确认提交
成功时，摘要不得将其改写为下载或入库完成。

## 异常处理

- 发送模型前仍由 `ai/history.ts` 补齐缺失工具结果、移除孤立结果和重复结果。
- 压缩请求失败但估算使用量低于上下文窗口 95% 时，本次继续使用原活动历史，下一次
  模型调用可以重试压缩。
- 估算使用量达到窗口 95% 且压缩仍失败时，当前请求返回明确错误，避免继续发送必然
  超过窗口的请求。
- 压缩是有损操作。近期用户原话和稳定业务 ID 单独保留，用于降低摘要遗漏导致的
  错误操作风险；涉及外部修改时仍必须重新读取工具状态。
