# Pi 式滚动上下文管理

Updated: 2026-08-14

AutoFilm Core 的主 Agent 只保留一种会话压缩模型：滚动压缩较早消息前缀，同时保留
近期原始消息的 Token 尾部。该设计参考 Pi 的 compaction checkpoint 机制。Core
负责计算边界、生成摘要和持久化检查点，不依赖供应方的远程会话状态或专用压缩接口。

## 唯一的模型视图

未压缩时，模型读取当前会话的全部原始消息。首次压缩后，模型视图固定为：

1. 一个替代较早消息前缀的压缩检查点；
2. `through_sequence` 之后未经摘要的近期原始消息。

后续达到阈值时，Core 只把已经逐渐移出近期 Token 尾部的消息并入旧检查点，再生成
一个新检查点。不存在固定消息条数截断、影视主题摘要、额外用户原话副本或多层摘要
拼接。

`messages` 始终保存用户消息、Agent 消息、工具调用和工具原始结果。压缩只改变发给
模型的视图，不覆盖原始记录。`conversation_compactions` 每个会话只保存最新检查点、
压缩截止序号、Token 估算和压缩次数。

## 不参与压缩的固定上下文

以下内容不写入压缩检查点，而是在每次主模型调用前重新构造：

- 数据库中的 `agent.main` 系统提示词；
- Asia/Shanghai 当前时间和同一时刻的 ISO 时间；
- 当前成员的长期记忆。

“每次主模型调用”包括同一用户请求内的每个工具迭代，以及达到工具轮次边界后的最终
回复请求。因此，滚动压缩或长时间对话不会移除系统规则和成员长期记忆。成员长期记忆
按用户隔离，`/new`、`/clear` 和 `/reset` 不删除长期记忆。

## Token 参数

每个模型配置保存四个上下文参数：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| 上下文窗口 | 128,000 Token | 供应方为模型提供的完整窗口 |
| 自动压缩阈值 | 窗口减 16,384 Token | 为模型回复及压缩保留空间 |
| 近期原始历史 | 20,000 Token | 压缩后继续原样保留的消息尾部 |
| 单工具输出预算 | 12,000 Token | 限制模型视图中的单项结果，不修改数据库原文 |

管理员可在“AI 与模型”页面覆盖这些参数。自动压缩阈值最多为“上下文窗口减 4,096
Token”，近期原始历史必须小于自动压缩阈值。Core 在发送请求前使用跨协议保守估算，
并将供应方返回的实际输入 Token 用量作为同一任务下一次判断的补充依据。

## 压缩流程

1. Core 重新注入系统提示词、当前时间和成员长期记忆，再拼接当前模型历史。
2. 工具结果生成受限模型视图，原始工具结果保持不变。
3. 估算输入或上一轮实际输入达到自动压缩阈值时，从消息尾部向前累计近期 Token。
4. 达到“近期原始历史”预算后确定边界；边界不会落在孤立工具结果之前。单次交互特别
   大时可以从交互中间保留，检查点提示会要求保留交互前半段的目标和必要标识。
5. 旧检查点与本次移出的较早前缀交给 `conversation.compactor`。材料超过预算时按
   最高 48,000 Token 分块，逐块更新同一个检查点，请求不提供工具。
6. 新检查点覆盖旧检查点，压缩截止序号向前移动；近期原始消息不改写。
7. Core 再次从数据库构造模型视图，继续当前任务。

默认检查点按“目标、约束与偏好、进度、关键决定、下一步、关键上下文”组织，保留
TMDB/Jellyfin Item、任务、候选、workspace、字幕引用、必要路径和授权状态。大段候选
清单、失效临时链接、日志和无后续意义的中间步骤不保留。业务状态仍以工具查询结果
为准。

## 历史恢复与请求重试

- `ai/history.ts` 在发送前移除孤立或重复工具结果，并为进程中断后缺失的结果生成明确
  的恢复结果；该处理不构成另一层摘要。
- 供应方因 408、409、425、普通 429、5xx、网络中断、超时、服务过载或临时处理失败
  返回错误时，统一 AI 客户端最多自动重试 3 次。
- 存在 `Retry-After` 时按该值等待；否则使用 500ms 起步的指数退避并加入随机抖动。
- 鉴权、余额、计费、永久配额和普通请求参数错误不重试。
- 供应方明确拒绝旧工具历史格式时，Core 仍保留一次“系统提示词 + 当前用户请求”的
  兼容恢复。这是协议错误恢复，不会创建摘要或覆盖数据库历史。
- 压缩请求失败且上下文仍低于窗口 95% 时，本次使用原视图；达到 95% 时返回明确错误，
  避免发送必然超过模型窗口的请求。

`/new`、`/clear` 和 `/reset` 删除当前会话消息及其唯一压缩检查点。成员长期记忆继续
保留，并在下一次新会话调用时重新注入。
