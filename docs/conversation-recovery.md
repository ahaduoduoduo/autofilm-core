# Conversation history recovery

Updated: 2026-07-30

## 数据模型

Core 将用户消息、Agent 消息和每个工具结果分别保存到 SQLite `messages` 表。
一轮带工具的请求通常包含：

1. 用户消息。
2. 带一个或多个 `toolCalls` 的 Agent 消息。
3. 与每个调用 ID 对应的工具结果。
4. 后续 Agent 调用或最终回复。

工具调用和结果是一个不可拆分的协议单元。OpenAI Responses、Chat Completions、
Anthropic Messages 和 Gemini GenerateContent 的外部格式不同，但都使用 Core
规范消息层中的同一组调用 ID。

## 上下文截取

会话仍以最近 80 条数据库记录为目标，不缩短成员已经使用的上下文。查询使用
SQLite `rowid` 作为稳定插入序号，不使用可能相同的毫秒时间排序。

如果第 80 条边界位于一次用户请求的中间，Core 会向前扩展到该次请求的用户消息。
因此实际发送数量可以略高于 80，但不会出现以下无效组合：

- 只有工具结果，没有发起该结果的调用。
- 保留多工具调用中的部分结果，同时丢失调用消息。
- 相同毫秒内写入的 Agent 消息和工具结果顺序变化。

## 发送前恢复

`ai/history.ts` 在所有供应方协议转换前统一处理规范消息：

- 孤立工具结果直接从本次模型输入中移除，SQLite 原始记录保持不变。
- 同一调用 ID 的重复结果只保留第一个。
- Agent 调用存在但结果因进程中断未保存时，生成一个明确的可恢复错误结果。
- 模型收到恢复结果后应读取当前服务状态，不重复猜测可能带副作用的操作。

恢复只影响发给模型的视图，不删除聊天、任务或字幕工作区数据。

## 供应方重试

若供应方仍返回以下工具历史不一致错误，Core 自动使用系统提示和当前用户请求重试
一次：

- `No tool call found for function call output`
- `No tool output found for function call`

其他错误，例如鉴权失败、限流或模型不可用，不使用该重试，继续按原错误返回。

## 现有会话

升级不需要清空数据库，也不需要执行会话迁移。旧会话在下一次请求时即时构造完整
历史。此前因工具历史 400 中断的会话可以继续发送消息，原有用户请求、工具结果和
任务记录仍然保留。
