# Conversation history recovery

Updated: 2026-08-14

## 数据模型

Core 将用户消息、Agent 消息和每个工具结果分别保存到 SQLite `messages` 表。一轮带
工具的请求通常包含用户消息、带 `toolCalls` 的 Agent 消息、对应工具结果，以及后续
Agent 调用或最终回复。

OpenAI Responses、Chat Completions、Anthropic Messages 和 Gemini
GenerateContent 的外部格式不同，但都使用 Core 规范消息层中的同一组调用 ID。

## 活动上下文

尚未生成压缩检查点时，模型读取当前会话的全部原始消息，不按消息条数截断。达到模型
Token 阈值后，Core 把较早前缀写成一个滚动检查点，并保留配置数量的近期原始 Token。
后续压缩只将逐渐移出近期窗口的消息并入同一个检查点。

模型输入是“最新检查点 + 压缩截止序号之后的原始消息”。`messages` 原始记录不删除。
系统提示词、当前时间和当前成员长期记忆在每次主模型调用时单独重新注入，不依赖压缩
检查点。详细说明见 `context-management.md`。

## 发送前工具历史恢复

`ai/history.ts` 在所有供应方协议转换前统一处理规范消息：

- 孤立工具结果从本次模型输入中移除，SQLite 原始记录保持不变；
- 同一调用 ID 的重复结果只保留第一个；
- Agent 调用存在但结果因进程中断未保存时，生成明确的可恢复错误结果；
- 压缩边界不会让近期原始历史从孤立工具结果开始。

恢复只修复工具协议结构，不创建摘要，也不删除聊天、任务或字幕工作区数据。

## 供应方自动重试

统一 AI 客户端对临时处理失败、服务过载、超时、网络错误、普通限流和可恢复 5xx 最多
自动重试 3 次。存在 `Retry-After` 时按响应头等待；否则使用带随机抖动的指数退避。
鉴权、余额、计费、永久配额和普通参数错误不重试。

若供应方明确返回以下旧工具历史不一致错误，Core 在常规重试之外，使用系统提示词和
当前用户请求执行一次协议兼容恢复：

- `No tool call found for function call output`
- `No tool output found for function call`

## 现有会话升级

升级不需要清空数据库。迁移会删除旧影视主题状态和主题摘要表，并把压缩表转换为单一
检查点结构。已有 `messages` 继续保留；尚无检查点的旧会话在下一次请求时读取完整原始
历史，达到 Token 阈值后生成首个滚动检查点。
